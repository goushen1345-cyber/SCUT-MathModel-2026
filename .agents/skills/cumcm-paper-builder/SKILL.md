# 从真实研究材料形成可读论文

先读 [授权](../../../workflow/rules/governance.md)、[聊天](../../../workflow/rules/chat.md)、[证据](../../../workflow/rules/evidence.md)；读取项目状态、来源和写作范围，涉及状态含义时读 [状态协议](../../../workflow/rules/state.md)。直接调用也要检查权限；起草本身不修改研究 stage。材料不唯一时先查既有记录，不能猜项目或采用失效版本。

## 按请求选择模式

| 模式 | 输入和许可 | 产物与停止边界 |
|---|---|---|
| 局部起草 | G0/G2 或当前小问 B/D 已确认的相应材料，且请求或既有计划包含该写作范围 | 写指定章节草稿，列依据和待补项；不要求所有问冻结，不推进研究 |
| 单问修订 | 同一问的新验证材料或对已有章的审阅反馈 | 在既有稿上更新实际变化，保留版本；未冻结结果不冒称最终 |
| 全文规划 | 所有必要问冻结有效，处于 PAPER_PLAN | 提出“问题—机制—答案—验证—边界”故事线、章节职责、图表和篇幅预算，通俗解释后停在 P；规划本身不要求 P 已获批 |
| 全文整合 | P 已批准，处于 PAPER，所有必要证据仍有效 | 以已审章节为底稿整合并完成摘要、结论、框架与版式；检查后停在 FINAL |

五类触发及交接字段只维护在 [阶段写作规则](../../../workflow/rules/evidence.md#阶段交接与写作) 与 [记录模板](../../../workflow/templates/records.md)。同一关口交接不增加机械批准；写作范围不明确时说明具体可写内容及来源，而不是申请推进研究。

## 写作与修订

1. 读 [论文高手指南](references/expert-paper-writing.md) 当前章节与交付部分。数据章按需读数据指南；单问章按需读 modeling.md。写摘要时再读 [摘要专项指南](references/expert-abstract.md)，不让早期起草加载无关材料。
2. 检查主要研究报告、数学表达、实际比较、图表说明及主张来源。区分未做研究、尚未找到记录、现有事实没有写清；先查/补现有材料，新增计算需要相应研究许可，不能在润色时偷改数据模型。
3. 用有含义的模型名称组织正文。确定性主张在内部证据映射中能追溯；正文使用正常公式、图表、文献引用，摘要不出现审批、冻结、run ID 或无解释的内部代号。支持不足的内容明确限定或不写为结论，不强造成功故事。
4. 重要方法前解释动机；关键公式给变量、条件和现实含义；结果连到方案变化和问题答案；图表有正文解读。首次概念先通俗解释再准确表达。以一个完整且有真实材料的论证单元校准样章；已有确认样章则沿用，不每章新设确认点。
5. 前置稿按 [论文转换方法](references/expert-paper-writing.md#前置章节的论文转换) 区分背景、重述、分析、总体思路职责；逐段检查中心和信息增量，给重复内容明确的移动/删并/重写去向。待核事项完整留在内部，正文以判断—依据—建模要求—必要边界推进，不提前定算法。整合保留已审章节中的必要解释，处理重复、符号、版本、衔接和编号。若删改改变论证或结论，说明具体影响；禁止根据状态日志重新生成压缩报告覆盖完整稿。
6. 图表、摘要和正文从同版本结果取数，统一单位与有效位数，检查舍入后方案可行。发现错误记录受影响主张并转回研究范围处理，需要重开时取得授权；写作不制造验证。

## 排版与交付

正式排版默认 LaTeX→PDF，保留可编译源文件与所需素材。环境不足说明缺失和替代方案，不静默改用 Word。正文、标题、题注、表内文字、公式编号、参考文献、页眉页脚全黑，表格白底黑线；图形颜色须有信息作用。

使用已安装且适用的文档/PDF 工具时先读其技能，按写作指南查看实际渲染页：公式、字体、图表、引用、跨页、裁切与异常留白。无能力时明确未检查，不以生成源文件或编译成功代表版面通过。页数是可调整预算，不为页数灌水，也不以“页数不等于质量”掩盖论证缺失。

核验当届官方论文、AI 使用、匿名、文件大小和赛区补充要求。读取真实 ai_usage_log 汇总声明与详情；缺实际人工核验须列待核验，不以 AI 检查冒充。检查代码运行依据、结果一致、附件齐全、匿名和引用真实；涉及新增复跑仍遵守研究许可。

向用户说明已检查与未检查事项、主要贡献和边界、文件位置，停在 FINAL。最终批准仅确认版本；上传需另行授权并满足赛事规则。科学正确、证据一致、可读性、约定版式和提交规范分别验收，可读性不能补偿错误结论。停 FINAL 前执行 [写作指南的 FINAL 赛场勾选](references/expert-paper-writing.md#final-赛场勾选写作交付) 与 [摘要勾选](references/expert-abstract.md)；摘要、正文、表、图、结果摘要须同源同版核对。

## 每问验证和代码图文整合

每问按“模型建立/求解—适用验证及结果—风险与边界—本问结论”组织。读取该问 report.md 的 Validation Plan/Results 与主张映射，准确写验证支持什么、未支持什么；**全文最后的综合评价不能替代各问验证，也不得把本问灵敏度/鲁棒性整段挪到文末充篇幅。** 某问没有验证证据时标记“研究未做”或先查缺失记录，交回研究方提出补做方案，不编写鲁棒、显著改进或最优性结论。

全文规划（P）时收集各问可验证的创新/改进主张：每条对应“不足—改动—同条件对照—图/表 ID—关键数字”；无对照证据不得写入摘要或评价的“创新点”。局部起草同样遵守 [人话书面语](references/expert-paper-writing.md#人话书面语防方法论说明书腔) 与边界密度规则。
论文候选图从项目 paper_evidence/figure_registry.md 选择，按 [代码生图规则](../../../workflow/rules/evidence.md#代码生图与图登记) 核对来源、源码、输入/逻辑、实际复现与视觉验收。需要生成时读取 [figure-support](../cumcm-figure-support/SKILL.md)，不能调用生成式图片或无源码手工图。每张正文图有图前目的、对象/单位/范围、图后真实发现及实际作用，不只写“如图所示”；适合精确数值或多维适配条件的内容优先判断表格/矩阵；正文解释含义，不重复整表。总体框架默认模型结构图，调用 Figure 前提供已确认共享骨架、每问 Model Delta、阅读目的、参数实际作用和边界；不足先回研究方补已有材料，不脑补。G0 尚无模型时按共享规则交建模要素草图/缺项，明确请求流程才用流程图。总体图通常放在分析/总体思路附近，图前说明为何看，图后以 1～2 段说明共享与增量，不逐框复述；用户限定文字时遵循范围。符号表自然引入，第一阶段仅放已确认公共符号。
