# 摘要专项指南

在全文规划时用于确定信息预算，正文主要结论稳定后用于写作与验收。早期可列待填框架，不能把预期结果写成事实。来源必须是当前有效正文和论文证据，不从 state 日志直接压缩生成。

## 读者需要在摘要里知道什么

第一段用简洁语言交代研究对象、核心困难和总体解决思路。随后按题目实际结构组织各问：要解决的关键困难、模型实际含义及选择动机、代表性结果和必要条件。末尾只在有支持时概括主要价值、验证或限制，避免重复空泛赞美。

“每问一段”是适合多问递进题的默认写法，不强制拆开本来共享同一结构的任务。不能为了固定句数省去关键结果，也不能装下全部实验。按当届摘要页数与格式分配信息，优先保证每问答案可读。

## 从正文筛选信息

1. 为每问确定真正回答原题的结论，再选能支撑它的少量关键结果；既保留量值/单位，也保留影响解释的情景、时间范围或约束。
2. 选择有辨识度的模型描述，例如“考虑销量上限与轮作约束的混合整数规划”，不要只有“优化模型”，也不要堆一串无用算法缩写。
3. 对比必须指出对象和条件，提升写基准、幅度、单位和代价；没有显著性检验或合适依据时不写“显著优于”。复杂方案未稳定胜出可以写保留简单方案及依据。
4. 如结论依赖重要代理假设、有限情景或近似求解，用简短限定保留条件。不要用摘要篇幅有限为由把不确定结论写成无条件事实。
5. 同一指标在摘要、表图和正文使用一致口径与有效位数，不列无意义的多位小数。没有定量结果时写有证据支持的定性发现，不造数字。

## 内部语言怎样转换

| 内部记录 | 摘要处理 |
|---|---|
| M0、M1、B0、M0-R1 | 查真实含义后改为模型或方案名称；不能按代号猜含义 |
| “已冻结”“通过 B/D 审批” | 写实际比较、选择与依据；批准不作为有效性证明 |
| run ID、state、证据编号、数据文件名 | 留内部映射，不作为摘要论证；正常学术术语不受此限制 |
| “获批代理口径下可行” | 准确说明所采用的近似假设及适用条件，不能改成满足原题全部要求 |
| “效果较好、创新性强” | 替换为真实结果、比较证据或有意义的结构特点；无依据就删除 |

## 带注释的自拟正反例

反例：“问题二采用 M0-R1，在 N10 下通过验收，性能优异，最终冻结；问题三使用改进算法，效果显著。”

缺点：对象和方法含义不明，没有关键答案，内部验收冒充科学证据，形容词没有支持。

正例模板：“针对【未来参数等真实不确定性】，我们构建【模型的实际含义】，并在【同条件评价方案】下与【有含义的基准】比较。结果显示，【真实关键结果，含单位、时期及必要条件】；考虑【实际风险或代价】，最终采用【方案含义】。该结论适用于【正文支持的范围】。”

它好在每句承担明确职责：难点与方法、比较及答案、决策与边界。该段仅为写法模板，不能填入虚构结果，也不能暗示每问都必须得到改进。

不成功改进也可以有清楚摘要：“在【评价条件】下，新增【结构】未带来稳定改善，因此保留【较简单方案】；【真实风险或条件】是影响方案选择的主要因素。”只有真实比较支持时才这样写，不能预设研究结局。

## 交付与验收

内部准备简短信息映射：摘要句子/对应小问｜模型含义｜关键结果和单位｜正文位置与来源版本｜比较条件｜必要限定。沿用论文证据区，不新增重复台账；正式摘要不附内部映射。

逐句检查：首次阅读能否理解每问解决什么、用了什么办法、得到什么答案？所有数字和贡献是否有正文支持？方法名能否解释真实结构？比较条件和单位是否清楚？是否混入冻结/审批/版本？摘要是否新增正文没有的结果？是否用过强语言隐藏局限？是否符合最终 PDF 的实际页数和可读性？

**赛场摘要勾选**（定稿前必过；团队排版约定可含关键词加粗，以当届模板为准）：

- [ ] 分段：总起 → 各问（可按结构合并）→ 检验/边界收尾；不是黑压压一段术语串
- [ ] 人话：能回答“解决什么→怎么做→得到什么→说明什么”，少堆“构建框架刻画”套话
- [ ] 无内部管理词：冻结、审批、M0/M1、run id、state、证据编号
- [ ] 关键数字与正文/表同源同版；有单位与必要情景；无正文没有的新数
- [ ] 比较写明对象与条件；无空喊“显著/创新”而无对照
- [ ] 脱离内部报告通读仍可懂

不能仅搜索字符串断言质量合格；例如模型自然简称与内部代号须按语义区分。最后脱离内部报告通读摘要，确认读者无需知道项目工作流即可理解。
