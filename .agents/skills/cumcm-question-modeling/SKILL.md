# 单小问研究

先完整读取 [授权](../../../workflow/rules/governance.md)、[聊天](../../../workflow/rules/chat.md)、[证据](../../../workflow/rules/evidence.md)、[状态](../../../workflow/rules/state.md) 和 [模型与验证指南](../../../workflow/rules/modeling.md)。读取活动小问、批准计划、数据和协议版本、上游产物；任何依赖失效先停。

## A 前：候选与试跑计划

重述本问交付与现实机制。审查四类搜索视角：A 基础稳健、B 经典结构/机制、C 先进数据驱动、D 题目定制。适用类别提出多个代表候选；不适用类别说明依据，不凑模型。类别可重叠，不能换名字伪造创新。

每候选解释原理和小例子、本题适配、数据需求、性能潜力、解释性、可能贡献、成本、风险、验证。未运行的判断标为预期。筛选真实值得试跑的候选，保留简单可行基准；编制固定比较口径、预算、允许文件和停止条件。保存 questions/Qk/report.md，讲解后停在 A。

## A 后 / B 前：实跑

只实现批准候选，在单独 runs/<run-id>/ 保存代码、参数、环境、日志和输出。可在批准范围内 debug、有限调参和重跑；不扩大模型/数据/预算。失败区分实现失败和方法表现差，不凭运行失败宣布模型不适用。

统一协议比较，不用虚构的“创新性分数”代替证据。报告表现、解释代价、稳定性、未验证风险与推荐；向用户推荐并解释，由用户选择主模型。停在 B。

## B 后 / C 前：深化设计

围绕获选 M0 的已发现不足提出机制、结构、求解、风险控制或验证改进；说明假设、可测贡献、对照、成本和停止条件。深化可以只补验证，也可以建议不加复杂性。停在 C，不直接进入全文写作。

## C 后 / D 前：深化与验证

执行批准方案，更新演化记录；允许无提升并回退。按模型类型做独立核验、基准比较、必要消融/敏感性、误差/风险分析。检查最终导出产物，不只检查模型内部变量。

逐问回答：解决什么、为何适用、核心数学思想、为何非其他候选、何证有效、告诉现实什么。保存实验索引和有效证据，讲解后停在 D。CORE 额外报告最薄弱证据、继续投入机会、代价及停止条件。

AI 不自动冻结。D 继续深化回到新的 C 计划；重选回 A/B；只有真实人工确认才冻结具体版本。进入下一问必须另有明确授权。每轮均更新 AI 留痕并提供随时可生成的审查包。
