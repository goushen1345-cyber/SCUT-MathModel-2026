# 单小问研究

先完整读取 [授权](../../../workflow/rules/governance.md)、[聊天](../../../workflow/rules/chat.md)、[证据](../../../workflow/rules/evidence.md)、[状态](../../../workflow/rules/state.md) 和 [模型与验证指南](../../../workflow/rules/modeling.md)。读取活动小问、批准计划、数据和协议版本、上游产物；任何依赖失效先停。

## A 前：候选与试跑计划

重述本问交付与现实机制。审查四类搜索视角：基础稳健（较少假设的可靠基准）、经典结构/机制（成熟数学表达现实目标与约束）、先进数据驱动（数据条件支持的结构学习）、题目定制（针对具体不足修改目标、约束或方法）。适用类别提出代表候选；**不适用类别一句话说明依据即可，不凑模型、不为凑齐四类硬塞同质变体。** 类别可重叠，不能换名字伪造创新。**试跑名额优先留给有对照价值、能回答选择问题的候选**；保留至少一个简单可行基准。

每候选解释原理和小例子、本题适配、数据需求、性能潜力、解释性、可能贡献、成本、风险、验证。未运行的判断标为预期。筛选真实值得试跑的候选后，编制固定比较口径、预算、允许文件和停止条件。保存 questions/Qk/report.md，讲解后停在 A。

## A 后 / B 前：实跑

只实现批准候选，在单独 runs/<run-id>/ 保存代码、参数、环境、日志和输出。可在批准范围内 debug、有限调参和重跑；不扩大模型/数据/预算。失败区分实现失败和方法表现差，不凭运行失败宣布模型不适用。

统一协议比较，不用虚构的“创新性分数”代替证据。报告表现、解释代价、稳定性、未验证风险与推荐；向用户推荐并解释，由用户选择主模型。停在 B。

## B 后 / C 前：深化与可信度验证设计

围绕获选 M0 的已发现不足提出机制、结构、求解、风险控制或验证改进。每问必须按 [可信度验证矩阵](../../../workflow/rules/modeling.md#每问可信度验证矩阵) 在现有 report.md 写 Validation Plan：最重要的不确定性、待验证主张、适用方法及不适用理由、对象/条件、判断标准、成本和停止条件。正确性与现实解释原则上必做；其余按题意选择。**若本问主张含排序最优、稳定、可推广、风险可控等，则灵敏度或鲁棒性至少一类须进入计划，或明确将主张降级为更弱表述；禁止为省事把整类标成“不适用”。** 深化可以只补验证，不强加复杂性。用 [C 点讲解要求](../../../workflow/rules/chat.md#c-与-d-的可信度讲解) 说明为什么值得做，再停在 C 等待确认；不直接运行新增验证。

## C 后 / D 前：深化与验证

只执行获批的深化与验证方案，更新演化记录和 Validation Results；每项关联计划、原始输出、实际条件、结果及对主张的支持程度。检查最终导出产物，不只检查内部变量。允许敏感、高风险、无提升、失败与回退，保留反证；未执行明确记“研究未做”，不把不适用与没做混淆。新增情景、参数范围、验证或超预算先回授权范围判断，不因需要画图而自动补实验。

逐问回答解决什么、为何适用、核心数学思想、为何非其他候选以及现实含义。D 前对照计划解释：已验证内容和结果、稳定结论、敏感点、最大风险、失效条件、依赖人为假设的结论、不能声称证明的内容、值得入文的验证及继续深化价值。保存实验索引、验证结果、有效主张和图表候选。关键正确性或核心主张证据缺失时指出缺口，不建议按已验证成果冻结；证据齐备也不自动冻结。最后才请求用户选择继续、重选或冻结。CORE 额外报告最薄弱证据、机会、代价及停止条件。

AI 不自动冻结。D 继续深化回到新的 C 计划；重选回 A/B；只有真实人工确认才冻结具体版本。进入下一问必须另有明确授权。每轮均更新 AI 留痕并提供随时可生成的审查包。

## 专业参照与两轮章节材料

在 [模型与验证指南](../../../workflow/rules/modeling.md) 中，A 前读问题结构与候选搜索，B 前读比较与解释，C 前读深化设计，D 前读对应题型验证与交接。重要方法先说明困难、通俗原理、小例子，再给数学含义；聊天使用路线中文名称，A/B/C/D 专指确认点，回复“选 B”若对象不清楚则澄清。

使用 [记录模板](../../../workflow/templates/records.md) 扩展本问 report.md，不把指标、代码和日志当完整研究说明。交付动机、假设、符号单位、目标/约束或统计表达、关键推导、求解步骤、候选实质差异、比较条件、实际演化、验证、现实解释、图表说明和局限。影响可行性的规则不能缩成“其余约束类似”。

- B 选定初始主模型后：交第一轮章节材料，说明已试与未试、为何选它、数学结构、已证不足和待做深化。尚未执行的计划用预期语气，不能写为提升。
- D 确认本轮结果后：更新第二轮材料，说明实际改动/回退、同条件对照、结果和方案结构变化、风险、现实含义与限制。选择继续研究时保留版本草稿，不标最终冻结。**推荐**在 report.md 维护可验证创新/改进条目（不足—改动—对照—图/表 ID—数字）；无对照不得写入“创新点”。写作交接遵守人话书面语，不把内部检查表贴进章节稿。
- 按 [阶段写作规则](../../../workflow/rules/evidence.md#阶段交接与写作) 起草不推进本问、不跨问、不自动批准 C。成熟材料可交组员或 Paper Builder；已授权研究可继续。

在现有本问 report.md 中按 [Model Delta 交接](../../../workflow/rules/modeling.md#model-delta-交接) 保留“共享模型骨架 + 本问增量”：B 首次有初始选型材料时写初版，D 随实际改动或回退更新，最终研究报告保留当前有效版本。不等冻结才整理，不把计划或未定关系写成已实现；该交接不新增报告或研究确认点。

## 图表与验证交接

B 后判断候选比较、模型结构或算法流程图是否有助解释选型；D 后从实际验证结果判断灵敏度、鲁棒性、风险、误差、消融或方案结构图是否有视觉价值。精确数值用表更清楚时不强画图。按照 [记录模板](../../../workflow/templates/records.md) 维护本问 Validation Plan/Results 与候选 Figure ID，再按 [图登记规则](../../../workflow/rules/evidence.md#代码生图与图登记) 交给 [figure-support](../cumcm-figure-support/SKILL.md)。验证研究仍由本 Skill 执行，先有结果才有验证图；图形辅助不能反向制造实验。

总体模型图优先交接研究方已确认的共享骨架、每问 Model Delta 和参数实际作用关系及必要来源，供 Figure 读取；不能让制图者从候选编号或运行日志猜模型。材料缺口交回相应研究交接区，图型与成熟度按上述图登记规则处理；图的结构与信息预算见 [模型图指南](../cumcm-figure-support/references/code-figure-guide.md#总体模型图的结构与信息预算)。

交给 Paper Builder 和 Reviewer 的不仅是图，还包括验证证明什么、没有证明什么、失败与假设边界及对应论文位置。每问验证放在该问模型/求解后、结论前，全文综合评价不能替代本问验证。
