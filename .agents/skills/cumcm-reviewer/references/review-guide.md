# 分阶段审查与面向新手的输出

## 审查节奏

全题理解后简短审查；数据冻结前、每问 B 和 D 重点审查；CORE 问增加 C；A 在路线争议、陌生方法或昂贵试跑时按需；全文最终确认前全局审查。风险突然出现可随时介入。该节奏是建议，不自动添加确认点或自行调用另一个对话。

## 按当前阶段选择检查

| 阶段 | 检查内容 | 不应强求 |
|---|---|---|
| 题意 | 原题要求、每问输出、歧义、依赖和CORE理由 | 尚未完成的模型实验 |
| 数据冻结前 | 字段/主键/单位、原始证据、获批范围、缺失类型、异常候选、前后影响、独立核验和来源 | 每种数据都标准化、每个极值都删除 |
| A | 候选实际差异、适配与数据条件、基准、比较协议、预算与停止条件 | 每类凑数、提前证明未经试跑的优势 |
| B | 同数据/约束/信息条件、划分泄漏、调参预算、失败与未试跑的区分、结果可信度、主模型推荐理由 | 因模型简单或指标不是最高就否定 |
| C | 深化必要性、每问验证矩阵与主张匹配、适用/不适用理由、范围依据、判断标准、成本和回退 | 全套同样验证、提前已有最终验证结果 |
| D | 最终导出物、独立重算、约束/统计条件、基准与必要消融、风险收益、稳定与失效范围、主张来源 | 用另一AI认同替代验证或宣称必然最优 |
| 全文 | 题目是否答全；摘要赛场勾选；摘要/正文/表/图同源；跨问依赖；真实演化；人话与过度防御；引用；图表公式；当届材料规则；创新主张是否有对照 | 固定页数当作硬门槛、术语数量或假装知道评委具体分值；把竞争力建议写成科学阻断 |

预测/分类重点检查训练与最终测试分离、预处理只在训练拟合、时序与分组泄漏。优化检查变量、单位、现实约束、求解状态及界、舍入后可行性，重算最终导出表。统计、评价、聚类检查推断条件、权重依据、不确定性，关联不说成因果。

## 问题卡

每个真实问题使用稳定ID（如 R01），复审沿用ID：

- 分级（三档，避免“没事”或“误报阻断”）：
  - **必须处理**：科学错误、题意硬条件未满足、关键数值矛盾、无证据的强主张等——影响冻结/选型/提交判断。
  - **建议补强 / 交付不达标**：约定黑字、公式不可读、摘要混入内部代号、同源数字不一致、人话同质句式过重等——应改，但不等于模型算错。
  - **竞争力建议（非阻断）**：国奖向缺口（缺对照、创新无指证、篇幅偏短未自检、图过挤等）——供用户取舍，不得写成必须处理冒充科学失败。
- 证据强度：已证实 / 待核验。严重后果但未核实的疑点写清“关键项未能确认”，不要伪称已证错误。
- 位置：文件、版本、章节/行/单元格/实验ID；无法定位时说明证据缺口。
- 问题是什么：一句普通本科生能懂的话。
- 为什么重要：会影响哪些数值、模型选择或论文主张。
- 依据与解释：原始要求、实际输出、推导或复算；首次概念可给小例子，不把示例数字写成本题结果。
- 最小处理：修正或验证步骤、验收证据、是否需新授权。

只给自己确认过的事实；代码未运行就写“静态检查发现风险”。“没有提供基准”与“基准一定更好”不同；没有置信区间也不必然构成所有问题的错误。材料不足时说缺什么、为何影响判断以及可先完成哪些部分。不把一般排版偏好当科学阻断；也不把竞争力建议升级成必须处理。

## 聊天输出结构

先给有边界的总体判断和最重要发现，用自然段解释，不先丢十几条术语：

> 当前审查的是【版本/范围】。最需要关注的是【问题】。通俗地说，【解释】；这会影响【决定/结论】。我依据的是【证据】，目前【已证实/尚待复核】。

再按分级列真实问题卡。对确实站得住的关键点可简短说明，但不写空泛表扬。无问题则明确没有发现，不为满足模板凑数。

最后说明：已检查什么、没有检查什么、有没有实际复算；当前范围结论；先交给 Worker 做什么；哪些决定必须由用户作出。报告不能代替聊天讲解，不因为提供了文件链接就省略关键解释。

## 复审关闭规则

输入应含上次意见、本轮diff/改动说明、修正版本、复算或验证证据。状态：未解决 / 已修复并验证 / 待证据 / 有证据不采纳。不能仅凭 Worker “已修复”或新一轮“看起来没问题”关闭。

发现上游改变要标明受影响的后续问与主张，但不自行改其状态。争议可给最小判别实验，由用户决定是否授权；不要求用户在两个AI的自信程度之间选边。

## 写审查报告时

仅在用户指定独立输出位置时创建新报告，包含本轮范围/版本/已查材料、问题卡、复审状态与能力限制。不要修改 review_package 的原输入，更不能写 state.json、决策台账或冻结快照。由 Worker 汇入正式账本并记录 Reviewer 的 AI 参与，不能当成人工核验。

## 专业质量参照与到期产物

数据审查按需读 [数据高手指南](../../cumcm-problem-data/references/expert-problem-data.md)，建模审查读 [建模指南](../../../../workflow/rules/modeling.md)，章节/全文审查读 [论文指南](../../cumcm-paper-builder/references/expert-paper-writing.md)，摘要审查读 [摘要指南](../../cumcm-paper-builder/references/expert-abstract.md)。按当前对象读对应部分，不把示例当本题事实，不机械索取每份指南的全部产物。

| 当前对象 | 补充检查 | 到期边界 |
|---|---|---|
| G0 题意材料 | 现实矛盾、各问难点、事实/假设、前置章节职责、题意支持的建模要素和可写范围 | 不要求候选实跑或已建成模型；不以流程链冒充模型结构，明确请求流程时按该类型审 |
| G2 数据材料 | 审计与 EDA 分开；真实处理/保留理由；图表解释与推断边界；可写交接 | 冻结前查交接材料，不以尚未起草完整章阻止合理数据核验 |
| B 选型材料 | 公平比较、选型理由、初始完整数学表达、已知不足 | 写作第一轮在 B 选择后；不提前要求深化成功 |
| C/D 深化与验证 | 不足—改动—对照—结论；实际方案含义、风险、关键约束和失败 | D 后才交第二轮；继续研究不要求最终定稿 |
| 章节草稿 | 动机、公式含义、图表解释、自然衔接、主张支持与来源 | 按已授权章节审，不要求其他小问或全文摘要 |
| 全文/FINAL | 已审章节保留；跨问一致；摘要独立可读且过勾选；数字同源；各问验证位置正确；黑字与公式；PDF 和提交材料；竞争力缺口单列 | 只有到全文交付时检查全套适用项 |

数字和代码俱全，但缺关键约束表达、比较理由、结果解释或图注，应定位交接缺口并说明怎样补。内容没写清不等于实验没做；查明后给最小修正，不自动要求重新建模。

区分科学错误、已约定交付要求不达标、普通优化建议。黑字已经约定时彩色标题须修正，属于交付问题；公式显示失败若妨碍核对数学含义应说明实际影响。正文不能用“已批准代理口径”代替满足原题的证明，也不能把硬约束违规仅写进局限就宣布合格。

语言问题按修订后的具体段落复审；视觉问题看最终渲染页面与版本；数学/数值问题看推导、原始依据或独立复算。记录所看页面和范围；只有源文件或截图时，不声称检查了整份 PDF。Worker 的“已修复”与另一 AI 的同意都不足以关闭问题。

## 前置章节的表达审查

先读 [前置章节的论文转换](../../cumcm-paper-builder/references/expert-paper-writing.md#前置章节的论文转换)，以同一参照检查实际文本。先确认被审对象属于聊天解释、内部研究记录还是论文正文：聊天兼有教学和研究管理职责；内部报告的未知、待办、风险、歧义和待核证据应完整保留；以下表达检查针对面向读者的论文转换，不能借此删减研究记录。

### 章节职责冲突与信息增量

- 检查背景是否说明现实矛盾；重述是否集中于对象、已知条件、主要约束、逐问任务和输出；分析是否推进到“困难—简单处理为何不足—模型所需能力”；总体思路是否给出共同基础、逐问新增因素和统一输出。重述中的深入解释应定位到分析；分析无需再次完整转述任务；总体思路无需再讲一遍逐问难点。
- 对重要段落，用一句话写出其核心任务，再指出相对前文新增的判断、机制或结构关系。无法说明中心或信息增量时，明确建议拆分、移动、合并还是重写，并标明去向。不要把必要承接句、关键条件的简短回指一概判为重复。
- 分析停在“后续需要研究/核验”时，检查能否由已知困难推出模型需要的表示、约束、计价或比较能力。要求补建模含义，不提前指定算法、补实验或将未验证口径写成事实；真正未确定的口径继续留在内部记录，在正文中保留影响读者理解的必要限制。
- 地类、季次、适种条件等多维长列表，检查是否适合条件表、关系矩阵、时间格图或代码结构图，并说明拟承载的具体信息；正文解释关键含义，不能逐格重复。总体思路在模型材料成熟时用模型结构图加 1～2 段解释；模型不足不要求脑补，只有明确请求流程才用流程型图，不为版面凑图。
- 篇幅只作信息密度提示：背景通常 1～2 段，分析允许充分解释，总体思路应明显短于逐问分析。不得以固定字数直接判定优劣；具体项目的编辑数字按论文指南作软参考，不扩为其他题的硬门槛。符号表应有自然引入，G0 只列已确定公共符号，不要求补齐尚未选定模型的变量。

### Excessive Defensive Writing（过度防御式写作）

定位连续出现“不能、尚未、后续需要、仍须、应说明、应界定”等、同一边界反复解释、内部待办直接进入正文、只有警告却没有中心判断、或段段“因此模型需要……”同质收束的段落。词频只作诊断线索，不设禁词或数量阈值，也不能仅凭用词多少判失败。

逐项区分，再提出修正：

| 类别 | 判断依据 | 允许的处理与保留要求 |
|---|---|---|
| 必须保留的严谨边界 | 删除后会把模拟写成事实、相关写成因果、未核口径写成确认，或隐藏真实局限与适用条件 | 保留足以限定主张的说明；独立阅读的摘要、图注或关键结论必要时仍应就地重申 |
| 可重新组织的防御表达 | 同一限制完整重复，工作待办代替建模含义，连续警示遮住判断，或检查表式“应……应……”连排 | 改为“主要判断—原因/机制—必要边界”；每段末至多一句边界；内部未知保持完整 |
| 人话/说明书腔（多为竞争力或交付建议） | 通篇主语只有“模型”；抽象名词无例子；分析像方法论清单 | 建议改写节奏与主语；标为非阻断除非已导致主张不可读 |

例如，“经验范围未给出概率”在重述和分析同时展开时，重述保留题面给定范围与任务；分析解释范围本身不足以支持概率型风险结论，并说明模型需要区分范围变化与概率假设。若论文确实使用人工设定概率，该设定性质仍需在相应主张附近明确，不能改成已观测规律。

称谓检查：正文宜统一“问题1/2/3”，与图注一致。
表达问题卡在既有字段后补充：**原段位置与核心任务、造成的阅读影响、移动/删并/重写动作与具体目的地、应保留的独有信息和事实边界、复审方式**。例如不能只建议“删掉尚未”；应指出“将重述第 X 段的概率解释移至分析第 Y 段，合并已有同义说明，重述保留经验范围；核对修订段落仍未把范围解释成概率，并核对内部待核记录未被删改”。如果建议删除整段，必须交代其独有信息在哪里保留；确无独有信息才可说明整段冗余。

复审比较实际修订段落、图表与前后对应位置，检查职责更清楚、增量成立、段落有中心、建模要求有依据且真实边界没有丢失。若声称同步调整了内部材料，要核对差异；未提供对应材料就标为未核验，不凭作者自述认定内部记录完整。此类修订不要求重跑研究实验，也不构成跨阶段授权。

## D 点可信度专项

逐项检查本问计划和实际验证，不以标题、模型复杂度或图的数量计分：

1. 是否有真实可信度验证及原始依据，版本是否对应当前模型；仅模型运行不等于验证。
2. 方法是否匹配模型、数据、假设与最终主张，是否机械套栏目；必要正确性与现实解释是否覆盖。
3. 灵敏度对象是否关键，范围是否有依据；无合理对象时不强做。
4. 鲁棒性是否改变了适当的数据/样本/情景/条件，是否仅重复同一输入。
5. 风险情景和指标是否有现实含义、概率或范围依据，是否只报平均收益；不默认要求 CVaR。
6. 改进是否有统一条件下的直接对照，去掉硬约束的违规方案是否被当作合格基准。
7. 最终测试是否被反复用于选型，样本/情景/种子是否只挑有利项。
8. 随机性/初始化/预算是否适当核查；是否凭收敛曲线平稳就声称全局最优。
9. 不适用理由是否成立，没做是否被假称不适用；未执行项和负面结果是否保留。
10. 是否解释稳定/敏感点、最大风险、失效条件、人为假设依赖和未证明内容，以及继续深化价值。
11. 论文是否在对应小问解释验证证明了什么，全文末评价是否冒充本问验证；是否把本问灵敏度/鲁棒性整段挪到文末。
12. 图文是否忠实表达实际验证，无实验时是否标研究缺口而非“鲁棒性较好”。
13. 若主张含最优/稳定/可推广，计划中是否有灵敏度或鲁棒性或已主张降级；有无空喊创新而无对照。
证据不支持某项主张时允许调整/收缩结论和保留失败，不要求实验必然成功。原题硬条件未满足或核心验证未做，应指出其对冻结判断的影响；Reviewer 不自行冻结，也不补写主系统状态。

## 代码图形审查

按 [图登记规则](../../../../workflow/rules/evidence.md#代码生图与图登记) 和 [Figure Skill](../../cumcm-figure-support/SKILL.md) 核对源码、输入数据或结构定义、来源版本、实际复现命令/输出及视觉记录。图片经代码包装导出不等于代码生成；无源码手工最终图、生成式图片不满足团队交付规则。

总体框架默认模型结构图，先有可核对的共享骨架、各问 Model Delta、组件、边语义和来源，再审图；具体方法见 [模型图指南](../../cumcm-figure-support/references/code-figure-guide.md#总体模型图的结构与信息预算)。专项检查：

- 图型与中心：是否实为目录、研究流程或 Agent workflow？变量/目标/主要约束/中间计算是否成为视觉主体，而非“输入—试跑—比较—保留—总结”？只写“统一模型”标题不能通过。
- 关系：重要参数是否连到实际作用组件，是否只列名词或汇入一个“输入参数”大框？箭头方向与计算、约束、比较基准的语义是否准确？
- 共享和增量：是否只有一份真实共享骨架，各问变化作用于具体组件？是否误把评价新增画成目标改变、把计划画成实际、把参考方案画成后问锁定决策？
- 噪声与边界：排除热启动、候选代号、试跑、挑战者、留出、替换门槛、预注册、冻结和审批等内部过程。必要数学机制用准确名称且有依据；不按词表误删机制，也不借例外保留选型流水账。边界依附相关组件或图注，不做末端步骤。
- 短框与语义：一个主题、标题及最多 2～3 条短语；超过 4 行先拆结构，不缩字体。检查“累计面积代理→满足轮作”“无交叉响应→无关系”等改义，发现即不通过，要求恢复准确表达和重排。
- 快读：核对实际渲染及拟嵌入尺寸、10～20 秒检查记录。理工科读者不能快速指出模型、变量/目标、约束、共享、增量和输出时，要求重构并重新渲染复核。只看源码或元数据不能声明视觉通过，独立 AI 快读不冒称真实人类计时验收。
