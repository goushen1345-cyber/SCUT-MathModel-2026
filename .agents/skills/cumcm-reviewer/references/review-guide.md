# 分阶段审查与面向新手的输出

## 审查节奏

全题理解后简短审查；数据冻结前、每问 B 和 D 重点审查；CORE 问增加 C；A 在路线争议、陌生方法或昂贵试跑时按需；全文最终确认前全局审查。风险突然出现可随时介入。该节奏是建议，不自动添加确认点或自行调用另一个对话。

## 按当前阶段选择检查

| 阶段 | 检查内容 | 不应强求 |
|---|---|---|
| 题意 | 原题要求、每问输出、歧义、依赖和CORE理由 | 尚未完成的模型实验 |
| 数据冻结前 | 字段/主键/单位、原始证据、获批范围、缺失类型、异常候选、前后影响、独立核验和来源 | 每种数据都标准化、每个极值都删除 |
| A | 候选实际差异、适配与数据条件、基准、比较协议、预算与停止条件 | 每类凑数、提前证明未经试跑的优势 |
| B | 同数据/约束/信息条件、划分泄漏、调参预算、失败与未试跑的区分、结果可信度、主模型推荐理由 | 因模型简单或指标不是最高就否定 |
| C | 已发现不足→改动假设→可验证收益，成本、反例和回退计划 | 每个模型必须复杂化、必须融合 |
| D | 最终导出物、独立重算、约束/统计条件、基准与必要消融、风险收益、稳定与失效范围、主张来源 | 用另一AI认同替代验证或宣称必然最优 |
| 全文 | 题目是否答全、摘要与正文数值、跨问依赖、真实演化、引用、图表公式可读性、论文证据与当届材料规则 | 固定页数、术语数量或假装知道评委具体分值 |

预测/分类重点检查训练与最终测试分离、预处理只在训练拟合、时序与分组泄漏。优化检查变量、单位、现实约束、求解状态及界、舍入后可行性，重算最终导出表。统计、评价、聚类检查推断条件、权重依据、不确定性，关联不说成因果。

## 问题卡

每个真实问题使用稳定ID（如 R01），复审沿用ID：

- 分级：必须处理 / 建议补强 / 可选优化。
- 证据强度：已证实 / 待核验。严重后果但未核实的疑点写清“关键项未能确认”，不要伪称已证错误。
- 位置：文件、版本、章节/行/单元格/实验ID；无法定位时说明证据缺口。
- 问题是什么：一句普通本科生能懂的话。
- 为什么重要：会影响哪些数值、模型选择或论文主张。
- 依据与解释：原始要求、实际输出、推导或复算；首次概念可给小例子，不把示例数字写成本题结果。
- 最小处理：修正或验证步骤、验收证据、是否需新授权。

只给自己确认过的事实；代码未运行就写“静态检查发现风险”。“没有提供基准”与“基准一定更好”不同；没有置信区间也不必然构成所有问题的错误。材料不足时说缺什么、为何影响判断以及可先完成哪些部分。

## 聊天输出结构

先给有边界的总体判断和最重要发现，用自然段解释，不先丢十几条术语：

> 当前审查的是【版本/范围】。最需要关注的是【问题】。通俗地说，【解释】；这会影响【决定/结论】。我依据的是【证据】，目前【已证实/尚待复核】。

再按分级列真实问题卡。对确实站得住的关键点可简短说明，但不写空泛表扬。无问题则明确没有发现，不为满足模板凑数。

最后说明：已检查什么、没有检查什么、有没有实际复算；当前范围结论；先交给 Worker 做什么；哪些决定必须由用户作出。报告不能代替聊天讲解，不因为提供了文件链接就省略关键解释。

## 复审关闭规则

输入应含上次意见、本轮diff/改动说明、修正版本、复算或验证证据。状态：未解决 / 已修复并验证 / 待证据 / 有证据不采纳。不能仅凭 Worker “已修复”或新一轮“看起来没问题”关闭。

发现上游改变要标明受影响的后续问与主张，但不自行改其状态。争议可给最小判别实验，由用户决定是否授权；不要求用户在两个AI的自信程度之间选边。

## 写审查报告时

仅在用户指定独立输出位置时创建新报告，包含本轮范围/版本/已查材料、问题卡、复审状态与能力限制。不要修改 review_package 的原输入，更不能写 state.json、决策台账或冻结快照。由 Worker 汇入正式账本并记录 Reviewer 的 AI 参与，不能当成人工核验。
