# 微网与外部电网电力调控策略：支撑材料

## 文件用途

- `result1.xlsx`：问题一完整一天的购电安排、六组充放电量和日首尾储电量。
- `result2.xlsx`、`result3.xlsx`、`result4-2.xlsx`、`result4-3.xlsx`：对应各问2025年2月1日至12月31日共334天的完整结果。
- `code/`：数据处理、预测、调度、结果导出及检查的完整Python源程序。各计算模块由实际研究程序整理而来；`source_map.json`记录函数来源和整理前的校验值。
- `data/`：保留附件原数值的CSV压缩文件、时间映射后的数值输入以及问题一参数。CSV采用gzip压缩，Pandas可以直接读取；不需单独安装解压软件。
- `results/`：最终逐10分钟运行记录、逐日费用明细及问题三、问题四的每次调整记录。
- `templates/`：程序导出所需的空白结果模板，不是研究结果。提交结果在本目录最外层。
- `evidence/`：结果导出检查与独立复算记录。
- `AI工具使用详情.pdf`：可追溯的AI使用说明。

## 如何运行

使用Python 3.13环境，安装`requirements.txt`中的依赖。在本目录打开终端：

```text
python -m pip install -r requirements.txt
python code/prepare_inputs.py
python code/reproduce.py
python code/export_results.py
```

若需从原始Excel重新核对整理过程，将题目附件1—4及附件5按原目录结构放在`data/raw/C题/附件/`，并将题面放在`data/raw/C题/C题.pdf`，运行`python code/prepare_source_tables.py`。原始附件不重复放入支撑包；原数值和来源单元格已保留在随包CSV中。

`python code/explore_data.py`重算原有描述统计，输出到`reproduced/eda/`；`python code/validation.py Q1`重算问题一的规则对比与初始储电量检验。问题二、三的已有参数对照及问题三的信息条件对照可按`validation.py --help`选择运行，计算输出不覆盖随包最终记录。

第一条数据命令重建时间映射后的输入，并逐值核对。第二条计算命令重新求解问题一，衔接1月份库存，再分别复算问题二、三、四的最终方案；不读取已有订单作为这些问题的决策输入。其输出写入`reproduced/`，并与`results/`中的最终记录逐项比较，不覆盖提交结果。

可用`python code/reproduce.py --question Q3 --days 2`先检查运行环境；省略`--days`时计算完整334天。完整复算包含价格模型的重新拟合，耗时取决于机器性能。

最后一条命令根据`results/`的完整精度记录生成最外层五个结果表，并重新核算费用和设备约束。工作簿显示两位小数，单元格保留完整数值，费用按未舍入值汇总。

## 时间与费用的填写口径

一天分144个10分钟区间。计算数组的第0项为当日00:00—00:10，第1项为00:10—00:20，依此类推。输入数据按已确定的时间标签解释，不能再整体移动一格。附件二按连续日期衔接，不能把每一天的末行简单循环移到当天开头。

题目结果模板把00:00区间放在最后，因此购电表前143列依次填第1至143项，最后一列填第0项；问题一同理按行填写。模板中的“+1”标签原样保留；按本论文口径，日期行最后一列填写该日期00:00—00:10的量，全天总量与储电端点均使用同一自然日。

问题二和问题4-2的“计划购电量”表填写普通订单，费用不包含紧急购电。问题三和问题4-3的“计划购电量”表填写零点订单及原计划款；“调整购电量”表填写各时段最终有效总量，费用为最终普通电费加相对零点的净调整费。两张表的费用不能相加。所有分支的紧急购电另列，全年总费用见`results/daily_costs.csv`。

问题三和问题4-3每次发布后的完整安排保存在`results/*_adjustments.csv.gz`，包含零点、6点、12点、18点各次版本及相对零点的增减量。已经执行的时段不再改动，重叠调整不重复收取费用。这里的调整结算是本文已明确采用的口径。

充电量、放电量均在电池外侧计量，内部储电量按充、放效率各90%更新。“充放电量”表为实际运行结果。紧急购电只合并同一天内真正连续的区间；当天没有紧急购电时填“无”和0。

## 结果核对

问题一费用35126.85元；问题二13583810.84元；问题三13014172.33元；问题4-2为14248570.87元；问题4-3为13695929.70元。

问题一日首尾均为6000 kWh。1月1日沿用问题一的订单，从6000 kWh开始运行；随后以当时已有历史衔接1月份。2月1日共同起始储电量为8592.693560925925 kWh。之后各分支分别延续自身的实际余电，不要求每日首尾相等。

`results/*.npz`中的`execution`列顺序为：期初储电、期末储电、实际接收外网电、外网直供负载、光伏直供负载、外网充电、光伏充电、放电、紧急购电、未利用订单量、未利用光伏量、负载电量，均以kWh计。`q0`是零点计划；`versions`依次为0、6、12、18点版本，`order`是无日内修改权限分支的普通订单。

## 提交方式

电子论文与支撑材料分别提交，不将完整论文放入本文件夹。按2026年格式规范，使用WinRAR把本文件夹压缩成一个ZIP或RAR，压缩文件不超过20MB。论文附录须同时包括支撑文件清单与完整源代码；附录不计入30页正文。文件、属性及路径名称不得包含参赛者、学校或赛区信息。
