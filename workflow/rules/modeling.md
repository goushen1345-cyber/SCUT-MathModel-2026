# 按问题类型验证，不给所有题套机器学习

本文件同时承担建模高手指南：A 前读问题结构和候选搜索，B 前读公平比较，C 前读问题驱动深化，D 前读对应题型验证及交接。阶段字母是关口，四类搜索方向用中文名称。质量目标是以真实证据解释模型为何成立及为何这样选择，不以复杂度或模型数量代替研究深度。

## 候选与选择

四类视角 A基础稳健、B经典结构与机制、C先进数据驱动、D题目定制逐类审查；适用时多个代表候选，不适用时说明。选择不以公式多或算法新为理由。创新回答：本题哪里不适配、改了什么、为什么、解决什么、用什么实验证明。

基准应简单且满足同一现实约束。保留基准是对照和可交付后备，不保证它必定合格。先排除不合格候选，再用真实性能、解释代价、可靠性与预算取舍，不编造总分排名。

## 预测/分类

明确样本单位、预测时点及实际可获得特征。时间序列不随机打乱，重复对象检查分组泄漏。填补、标准化、PCA、特征选择只在训练折拟合。冻结划分、主次指标、种子与预算；选型/调参和最终测试分离。多次看测试集后不能仍声称独立测试。不能用训练准确率宣布有效。

## 统计、评价与聚类

先说明推断对象和假设条件，再选检验/估计；报告不确定性，必要时处理多重比较。综合评价权重和正负向变换有依据并做敏感性；聚类没有标签时不强行报准确率。相关、重要性和聚类差异不自动证明现实因果。

## 优化

逐项核对变量、索引、单位、目标方向、现实约束、不等号、整数性、Big-M依据、边界和求解状态。独立读取最终导出表，检查约束残差并重算目标；小规模可枚举或手算对照。可行解不等于已证全局最优，报告界、gap、终止原因与时限。

相同约束/数据/信息条件比较。放松约束得到更高收益不是可行策略改进；提前知道未来信息只能作理想上界。随机策略用统一独立测试情景，报告收益和风险的代价，不仅挑最好种子。

## 深化与停止

优先检验会改变结论的关键假设、机制约束、方案切换条件与失败反例。必要消融识别改进来自哪里，不为了齐全对所有参数机械加减百分比。发现错误先修正；无可靠改善就保留/回退，不包装。

CORE 在 D 点说明最薄弱证据、下一轮可测机会、成本、风险和停止条件。其余问也不自动冻结。任何预算耗尽只能报告，不能自动降低标准或越问。

## 从问题结构寻找候选

先定义输出和可用信息：是预测未来值、估计效应、资源分配、排序评价还是发现结构？谁在何时作决定，哪些量可控、哪些仅可观测、哪些未知？写出目标、约束、时间/空间/分组关系和不确定性，再寻找能表达这些结构的模型家族。

| 搜索方向 | 怎样展开候选 | 适用前提与常见误区 |
|---|---|---|
| 基础稳健 | 从简单统计、可解释规则、线性模型、可行规划等找可靠基准；可提出不同假设的代表方案 | 简单也需适配和验证；不能故意用违规或弱基准衬托复杂方案 |
| 经典结构/机制 | 识别整数决策、网络、动态、供需或概率结构，考虑成熟优化、统计和机制模型 | 用数学解释现实要求；公式长或模型组合多不等于正确 |
| 先进数据驱动 | 检查样本量、标签、有效特征及验证条件，比较树模型、核方法、神经网络等是否能补足基准遗漏 | 不能凭“先进”预判表现，少量汇总数据不足以支持复杂训练；缺乏数据时说明不适用 |
| 题目定制 | 从具体缺口修改目标、约束、特征、结构、评价或求解方法；与前三类可结合 | 改名、换库、调一个默认参数不自动是创新；必须有可测贡献与对照 |

优化题示例：先识别面积为连续决策、是否启用为整数决策、季次为索引、轮作为跨期约束；再判断线性/整数规划是否适合。不确定性有历史分布证据时可考虑随机规划，只有区间或情景依据时可考虑相应稳健方法；启发式适用也需可行性和质量证据。不能在没有时间序列样本时，为了四类齐全强上预测网络。

预测题示例：先明确预测时点、对象和真正可得变量，再从朴素/季节基准、统计模型、树模型等展开；方法差异应体现假设和可捕获结构。评价或统计题同样从推断对象、权重来源、样本设计和识别条件出发，不能强套优化或深度学习。

每个适用方向考虑多个有实质差异的代表候选；去重后筛选值得实跑的路线。不强制每类运行若干个、不预设四个最终模型。理论不适配、信息不足、成本过高和试跑失败分别记录。候选卡保留：原理和小例子、关键数学结构、数据/假设、区别、预期价值、代价、最大风险及可验证方法；未运行的优势标预期。

## 公平比较与现实解释

先固定比较问题与协议，再试跑。协议包含数据/划分/可用信息、实际约束、指标定义与单位、计算预算和停止条件。合理差异如不同模型的预算分配应说明依据，不拿不可比结果作统一排名。

比较表同时回答效果、可靠性、解释代价和实施代价。优化看目标、可行性、求解状态/界、风险和方案结构；预测看独立误差、分组误差与稳定性；评价看排名稳定性、权重影响和可解释性。报告相关条件下的差异，不制造创新星级和综合获奖分。

例如总收益上升时还要解释哪些资源安排改变、是否增加管理复杂度、是否以风险或放松条件换来收益。误差下降时检查改善集中在哪类对象、是否有少数组恶化。不能用一张总指标表替代为何选择的论证。

固定替换阈值必须有测量误差、实际成本或明确决策偏好的依据，不能把 Skill 中自拟的 0.1% 等数字当通用标准。最终测试不能反复用来挑选模型；若已用于选择须如实改变其角色并设计独立评价，不继续称其独立测试。

## 问题驱动的深化

每项深化写清：初始不足的真实证据 → 为什么该改动可能有效 → 实际改哪一处 → 与谁在何条件下比较 → 怎样判定收益及代价 → 失败时怎样回退。深化可以修结构、补关键约束、改善求解、控制风险或仅加强验证，不必换更高级算法。

自拟正例：初始优化方案产生大量细碎安排，经实际统计证实后，引入有业务依据的管理复杂度约束或第二目标，在相同资源与需求条件下比较收益让步、启用项数、可行性和敏感性。若启用项数只是一项代理，不直接宣称真实管理费用降低。

反例：“原模型太简单，所以换高级求解器并加 SHAP，创新性提高。”问题是没有识别真实不足；求解器变化未证明改善，SHAP 也不自动提升预测能力或提供现实因果证明。

若问题仅是论文未解释某约束，先补表达；若数学或代码遗漏约束，按实际影响回研究范围修正，不以润色掩盖。对硬条件的放松必须明确它改变了问题，不能只因用户批准近似就宣称满足原题。

## 数学表达、图表与两轮交接

在 [现有记录模板](../templates/records.md) 中保存变量/单位/索引/定义域、假设、目标或统计表达、关键约束与推导、求解方式、比较、验证和现实解释。独立检查员应能据此明白模型，而不是必须逆向完整代码才知道条件。

B 后的第一轮材料说明选型依据、初始模型和不足；D 后的第二轮说明实际改进/回退、结果、风险及局限。阶段起草遵循 [证据规则](evidence.md#阶段交接与写作)，不能把第一轮的预期写成第二轮成果。

用图表展示真正有解释价值的比较：目标与风险取舍、方案结构、误差分布、敏感区间等；选择由问题决定，不要求每题都有雷达图、消融全套或机械正负百分比。图注保留条件、单位、情景和来源，正文说明它改变了什么判断或帮助认识什么。

自拟交接段模板：“针对【实际困难】，初始模型采用【数学结构】，因为【题意/数据依据】。与【实际候选】在【统一条件】下比较后，【真实差异及代价】支持选择【方案】。进一步核查发现【不足及证据】，本轮【改动/仅验证/回退】的结果为【实际结论】；尚不能推断【边界】。”占位内容须来自真实材料；不要求每问必然产生不足或成功改进故事。

验收问题：候选区别是否来自实质结构？基准是否合格、公平？关键约束能否核对？未试/失败/较差是否分清？改动是否针对证据？最终导出物是否独立核查？读者是否知道结果对现实意味着什么？哪些条件改变会使结论失效？B/D 的材料能否直接支持相应章节？不以填满表格当作通过。

## Model Delta 交接

每问在现有 questions/Qk/report.md 的交接区增加简洁的 Model Delta，不新建报告。研究方先在现有全局或小问 report.md 中标明共享基础模型的真实来源位置和版本，再以它为基线说明各问增量；共享骨架只整理当前已确认的组成，不为填图预设同一模型或补选算法。若各问并不共享某一组件，明确实际差异，不能强行归一。

B 首次有初始选型材料时形成初版，D 根据实际改动、保留或回退更新；最终研究报告保留当前有效版本及必要的旧版本引用。继续研究不等待冻结，拟议增量、未定项和实际采用项分清，失效版本不能混入当前图。

核对同一版本的数学说明、实现与实际结果。计划与实现有差异时分别写出，注明真实确认范围；不能从旧计划拼出“仅新增某机制”，也不能以代码已运行追认批准。来源冲突保留为待核，交回研究方核对，未解决前不作为已确认模型关系入图。

使用 [Model Delta 模板](../templates/records.md#model-delta嵌入现有小问-reportmd) 记录共享基线与本问版本、参数增改、目标、约束、关系机制或中间计算、新增评价、输出变化及保持不变的共享部分。每项给出简短的“基线 → 本问”变化或明确不变/未定，关联必要的来源位置、主张及其真实适用版本，不复制实验日志。

供总体模型图使用的共享骨架应能定位决策变量、目标、主要约束、计算关系和输出；重要参数须说明作用于哪个模型组件、怎样作用，例如输入计算、限定可行范围或作为比较基准。只保留真实存在的关系和必要边界，不能把参数名清单当作模型结构，也不从相关性补造因果。Figure 优先读取这些研究交接材料和各问 Model Delta；缺失则返回研究方查找或整理现有材料，涉及新研究仍遵守原有授权。图型与阶段成熟度见 [图登记规则](evidence.md#代码生图与图登记)，布局、短语预算和语义核对统一见 [模型图指南](../../.agents/skills/cumcm-figure-support/references/code-figure-guide.md#总体模型图的结构与信息预算)。

## 来源边界

本节四类方法、例子和验收问题是团队标准与自拟说明，模型家族是条件性候选，不是固定菜单。用户指定参考论文可用于比较动机、数学解释与风险叙述；具体引文、页码和样例结论必须核对原文后注明，不把参考论文的选择直接当作当前题答案。

## 每问可信度验证矩阵

本节就是现有建模高手指南的“高手如何验证模型”，不另建 expert-modeling.md 或验证 Skill。每问从最终主张反推最可能使其失效的条件；B 后/C 前必须形成方案，C 确认后在授权范围执行，D 前逐项回填结果。A/B 已做的有效验证可引用并检查适用版本，不为填矩阵重复运行。

首先问：关键参数变化后是否成立？数据/样本/情景变后怎样？不利情况损失多少？去掉改进后怎样？在哪些对象上误差大？哪些判断来自真实数据，哪些来自人为假设？目前证据允许说到什么程度？这些是适用性判断问题，不意味着每项都必须新增实验。

| 验证类别 | 回答什么、什么时候适用 | 设计与防误用 |
|---|---|---|
| 正确性/可行性 | 所有小问原则上必做：是否算错、违背题意或数学条件 | 优化回读导出表重算约束/目标、索引单位、取值与舍入；其他题核对定义、计算及模型条件。运行成功不证明正确 |
| Baseline/候选对比 | 选择最终方案或声称更好/值得采用时需要相应比较依据 | 同数据、信息、约束和评价条件；如无实跑对比只能限定为适配理由，不声称性能胜出 |
| 灵敏度 | 有关键权重、阈值、风险系数、代理假设、未知或关系参数 | 优先会改变结论的参数，范围依据现实/测量/决策需求；同时看结果值和方案切换，不能机械全参数±10% |
| 鲁棒性 | 数据、样本、情景、初始条件或假设扰动可能影响结论 | 明确改变什么、为什么合理，保留比较口径；重复同一确定性输入不证明鲁棒，场景有限不外推普遍稳健 |
| 风险 | 未来不确定性或收益/损失取舍影响决策 | 按实际依据考虑不利情景、尾部、最大后悔、压力测试或确已实现的 CVaR；写损失方向/基准/尾部口径。没有概率依据的情景不假装概率样本，不编灾害 |
| 误差 | 回归、预测、分类、拟合等有误差概念 | 分对象、区间、时间、区域或类别找表现差的部分；说明样本量及口径，勿用总体均值掩盖差异 |
| 消融/改进对照 | 声称模块、特征、结构、约束或融合有贡献 | 优先原模型 vs 只加该改动，同条件比较；多个改动混在一起无法归因。去掉题意硬约束所得违规方案只能诊断，不作合格竞争方案 |
| 随机性/收敛稳定性 | 随机启发式、初始化、训练或搜索 | 合理多种子/初始化、统一预算、分布与失败率，必要时看预算曲线；不选最好种子，曲线变平不等于全局最优 |
| 现实解释 | 几乎所有小问必做：结果表示什么、是否合常识、如何指导决定 | 回答方案变化/误差/风险的实际意义，合理性检查不代替数值证据；相关性和解释工具不证明因果 |

原则上必做的是题意/数学/结果正确性、与核心主张匹配的验证和现实解释。若这些关键项缺证据，应记待验证与限制，不能用“不适用”省略。其他类别逐类作简短适用判断；可以共享同一实验的证据，不必各生成一份报告或一张图。不适用写模型/数据/主张的具体理由，未执行写“研究未做”，执行后不支持也如实保留。

**主张与灵敏度/鲁棒性挂钩**：若本问准备主张“最优/较优排序稳定”“方案在扰动下仍可接受”“结论可推广到……”，则 Validation Plan 中须包含灵敏度或鲁棒性至少一类，或主动把主张改写成更弱、与证据匹配的表述。禁止为省事将整类标“不适用”却保留强主张。仍不要求机械做全参数±10%或全套方法。

确定性组合优化的自拟说明：“本问没有训练样本或随机过程，交叉验证与随机种子检验不适用。验证集中于最终表可行性、独立目标记账、求解界及现实解释；若管理参数为人为设定，则进一步设计其敏感性。”这里“无随机性”不能用来免除真正存在的管理参数问题。

含权重模型应主动检查权重依据和结论对合理变化的反应；未来资源配置应主动判断只看平均收益是否遗漏不可接受的损失。是否做尾部量或 CVaR 取决于信息、研究主张与预算，不能因算法名字常见就强制使用。

### C：深化与可信度验证方案确认

在本问 report.md 的 Validation Plan 中为待验证主张绑定验证 ID（如 Q1-V01），给出版本、最重要的不确定性、采用/不适用方法及理由、验证对象、参数或情景范围及来源、基准/控制条件、指标与判断标准、成本预算和停止条件。模板在 [records.md](../templates/records.md)。判断标准先定，依据题意、误差容忍或决策后果，不填无根据的统一阈值。

先解释当前模型最需要证明什么，再说明哪些检查值得做、哪些不适合、哪些昂贵。C 既批准深化也批准相应验证，允许只验证不改模型；把同批事项放一个既有关口，不另增验证阶段。批准前可整理现有证据和设计，不执行新增实验。计划发现新风险或范围变化时按治理规则处理，不偷偷扩预算。

### D：从结果到有边界的可信度总结

在 Validation Results 中逐项写实际执行、来源/run、版本/条件偏差、结果、支持/部分支持/不支持/仍待验证、失败和敏感点、风险、失效条件、假设依赖、可写表述和禁止夸大。未做的计划项保持“研究未做”并解释影响，不用空表或图替代。对比不能只留下有利指标、情景或种子。

在原有 D 点先向用户解释：验证过什么、发现什么、哪些稳定/敏感、最大风险、何时失效、哪些靠人为假设、哪些没有证明、哪些应写进本问、还值得继续查什么。不同结论可有不同支持程度；“模型可信”不作为一刀切标签。必要正确性或核心主张未获得证据时，明确缺口与补做/收缩主张方案，不能推荐按已充分验证成果冻结；已验证也仍需真实用户冻结授权。

失败的验证可以揭示模型不稳定或假设影响大，属于有价值结论。应保留真实材料并调整主张，不能换种说法伪装为“鲁棒性较好”。最坏情景只表示所评情景集合中的最坏；尾部结果、求解界和最优性术语要与真实证据一致。
