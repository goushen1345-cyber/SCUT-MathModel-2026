# 一条证据链，多个用途

任何重要操作形成：观察及来源 → 判断 → 候选 → 决策 → 理由 → 执行 → 核验 → 边界。记录可审查的理由与结果，不要求隐含思维过程。讲解写在聊天，技术证据写入文件，论文表述由同一事实派生。

## 最小账本

- state/state.json：唯一正式运行状态与授权引用；state.md 由脚本生成。
- state/decisions.md：按 ID 追加理由、候选、真实人类选择和版本；不再维护重复 rationale.md。
- state/ai_usage_log.md：重要任务后追加、阶段末汇总，记录工具/版本、用途、主要提示、产物、采用、人工修改和核验；人类未实际核验必须记待核验。
- questions/Qk/experiments.md：实验索引；每次运行的详细证据在 runs/<id>，记录数据/协议/代码/配置/环境/种子/终止条件/指标/失败。
- paper_evidence/data.md 与 Qk.md：主张、来源 ID、图表、支持状态、适用边界和可写表述。不把未支持结果当确定结论。

## 演化真实性

候选未试跑的淘汰理由只能是适配或成本判断；运行失败不自动证明方法差。M0 → 问题证据 → 改动假设 → M1 → 对照结果 → 保留/放弃。基础模型胜出、无显著改善、收益与风险取舍都是合法结论。论文可压缩过程，不隐瞒改变结论的反证。

## 独立验证与解释

最终数值追溯数据、代码、配置、运行和图表版本；检查器尽量采用独立路径、小样例或手算，不复制主程序错误。统计关联不等于因果，SHAP 不作现实因果证明。正文关键主张要能直接找到证据，完整日志不必堆入正文。

## 审查接口

按 workflow/templates/records.md 中的审查格式生成 review_packages/<审查ID>/review_package.md，使用本次冻结/候选版本的文件清单和哈希。外部对话不一定能访问本机路径：说明需上传哪些实际文件。截图只补充，不能替代公式、代码和输出。

审查对象含题面原文、协议、候选与失败结果，不只给 Worker 的推荐。Reviewer 默认只读，问题应给证据、影响、复现方法；允许材料不足。Worker 逐项记接受/反驳及证据/待检验；新权限回确认点。Reviewer 不能批准冻结，AI一致也不是独立验证证明。

独立审查使用 ../../.agents/skills/cumcm-reviewer/SKILL.md。Worker 生成的包还须说明本轮改动、上次问题ID及状态、当前拟作决定、直接/间接受影响产物。主执行者将 Reviewer 的工具、用途和真实核验活动汇入 AI 使用日志，不把 Reviewer 检查记成人工核验。Reviewer 不自己改共享账本。每条反馈的关闭需要修正版本与验证证据，不能仅凭“已修复”关闭。

## 三种表达层

同一事实服务三种表达：聊天用于教学与研究管理，完整解释未知、下一步与待决定事项；内部研究报告/证据区保留未知、歧义、风险、待办、待核证据、未验证与反证；论文正文面向读者组织问题、机制、建模要求、证据和必要边界。聊天解释不逐字变成研究报告，研究记录也不逐字转为论文。

内部记录不能因论文更流畅而缩水。转换时将排程和核验待办留在现有交接区，将读者必需的困难转成有依据的建模要求；未确认口径仍未确认，不靠润色消除事实缺口。需要独立理解的主张、图注或关键条件在当地保留必要限定；其余重复边界可合并并简短回指。具体章节分工、正反例与信息增量检查统一见 [前置论文转换](../../.agents/skills/cumcm-paper-builder/references/expert-paper-writing.md#前置章节的论文转换)，不新增报告层或状态字段。

## 阶段交接与写作

研究报告解释做了什么、为什么以及怎样核验；paper_evidence 保存主张、来源、有效性和可写范围；章节稿面向读者组织论证。三者共用事实与版本，不互相复制完整运行日志，不用 state.md 代替写作输入。模板统一见 [records.md](../templates/records.md)。

| 触发 | 可交接或起草内容 | 证据边界 |
|---|---|---|
| G0 题意确认后 | 背景、问题重述、问题分析、初步总体思路 | 路线未选定、结果未产生，不能提前定论 |
| G2 核验并确认数据版本后 | 数据来源与结构、实际处理及理由、EDA 发现和图表解释 | 不把未观测量写成补值事实，不虚构清洗 |
| 每问 B 选定初始主模型后 | 第一轮：动机、候选比较、选择依据、初始数学表达、已知不足 | 深化计划与收益只是预期 |
| 每问 D 确认本轮验证结果后 | 第二轮：实际改动/回退、对照、结果、风险、现实含义和局限 | 继续研究时仍是该版本草稿，确认结果不自动等于冻结 |
| 全文规划 P 通过后 | 整合已有章节，定稿摘要、结论、总框架和版式 | 全部必要问冻结有效；整合不删掉必要解释 |

在原有确认点完成研究讲解、交接和范围确认，不新增关口。起草由请求或既有计划授权；研究向前与组员写章不互相构成许可。已有授权允许时可以同时推进，遵守单写状态和并行边界。

交接区嵌入现有全局/小问 report.md 与 paper_evidence/data.md、Qk.md：问题与发现、方法理由、关键数学表达、比较或验证、图表解释、准确可写表述及禁止夸大、待补项、来源版本。前置章节范围放全局证据区；只有实际材料出现才建记录，不预生成多份空报告。

写作范围记录包括来源版本、目标章节/稿件路径、负责人、草稿/待复核/已审状态及审阅依据；是文稿元数据，不新增研究状态字段。已审必须说明谁审了什么，AI 自检不记成人类确认。纸面文字用正常模型名与学术引用；证据 ID、运行编号、批准和冻结信息留内部映射。

上游变化先列受影响的主张、图表、章节及使用位置，标记待复核，避免旧数字进入新稿。未受影响内容可保留；研究是否 stale 仍按正式状态协议处理。冻结快照不覆盖，改稿保存新版本；核对新版来源后才恢复使用。

发现写作缺口时先区分：研究未做（需相应研究许可）、记录未找到（先查来源）、解释未展开（据已有事实补写）。不为完整故事补造失败、人工推导或成功优化。最终整合从已审章节开始，统一符号、单位、版本、衔接、编号与版式，不根据流水账另起压缩稿。

AI 使用记录在重要任务后追加并于阶段末检查汇总完整性，覆盖数据/模型/写作/绘图/审查/排版。工具型号不可取得就记未知；不得事后猜造提示或人工核验。Reviewer 活动由主执行者汇入，AI 检查和真实人工核验分别登记；发现漏记只补可证实事实并标明补记，不倒填。

## 验证证据到论文

每问 report.md 维护 Validation Plan 与 Validation Results，字段与适用矩阵见 [建模指南](modeling.md#每问可信度验证矩阵) 和 [记录模板](../templates/records.md)。实验原始记录仍在 runs/ 和 experiments.md；计划、结果只引用，不复制一套日志。paper_evidence/Qk.md 将验证 ID、实际支持程度、反证、风险及边界映射到论文主张，缺失研究明确写“研究未做”。

可复核结果、同条件比较、未执行项和负面结果一同交 Paper Builder/Reviewer。来源变化使相关验证结论和引用图待复核；验证做过不代表仍适用于新版。研究方检查 C/D 交付并处理冻结语义，statectl 不会自动判断科学验证是否充分。

## 代码生图与图登记

团队硬规则：所有进入正式论文的图（含附录）都由代码生成，具有源代码、真实输入数据或已确认逻辑/结构定义、复现命令与环境、来源版本。禁止文生图、生成式图像模型、AI 无源码直接绘制最终框架图、无源码手工最终图，也不能把这些图片嵌入一段导出代码冒充代码生图。Mermaid 可作逻辑草图，最终图优先 Graphviz/TikZ/matplotlib；数据与结果图优先 Python/matplotlib，关系图按需 NetworkX/Graphviz。具体方法统一见 [figure-support](../../.agents/skills/cumcm-figure-support/SKILL.md)。

研究方确定分析发现和已确认的研究逻辑，Figure 只负责图表规划建议、代码表达、复现和图文接口；可按既有口径展示/汇总已给结果，不能拟合新模型、增加情景、参数扫描、消融或制造结论。缺实验标“研究未做”交回研究方，不因要图就自动补做。

框架图先有节点、含义、层次、边及每条边的语义，记录核对依据，再编码、渲染和视觉验收。已确认逻辑无须为每张图另增关口；新研究逻辑回对应研究决定。用户所说“总体框架图、建模框架图、总体模型图”默认是模型结构图：核心数学模型居中，表达变量、目标、约束、参数作用和各问对共享模型的增量。只有明确请求研究流程/论文思路流程/工作流程时才用对应流程型图，不能因模型材料不足静默改成流程或目录。内部管理图即使获请求也不冒充论文模型图；正式论文不含 Agent/Skill/Reviewer/Prompt/Freeze/state/审批/人工确认等内部标签。具体结构与信息预算统一见 [模型图方法](../../.agents/skills/cumcm-figure-support/references/code-figure-guide.md#总体模型图的结构与信息预算)。

唯一轻量图索引为项目 `paper_evidence/figure_registry.md`，首次有候选图时建立，模板在 records.md。每图稳定 Figure ID，记录来源、代码、输出、章节、图文接口和状态；报告、论文证据及稿件引用 ID，不各复制一份图卡。旧项目有图卡时合并/迁移为此单一记录，保留原来源并用引用替代重复条目。研究结论仍以研究报告/证据主张为准，registry 只引用它们。

G0 后判断总体/小问关系图；G2 后分类 EDA 图为正文、附录/支撑、内部检查；每问 B 后判断候选比较、模型结构/算法流程与选型解释图；D 后依据真实验证/结果判断改进、灵敏度、鲁棒性、风险、误差和最终结构图。没有表达价值不凑图，精确数值更适合表时保留表。G0 尚无共享模型时，只在题意确已支持的范围表达决策对象、目标含义、现实约束和已知作用关系，标为“建模要素草图”，不冒称已建成模型，不虚构变量/算法或用步骤链填空。连这些关系也不足时，先列缺项并交回研究方；已授权前置文字仍可完成。明确请求研究流程时可画相应组织关系。写作/绘图须在已有授权范围，用户限定只交文字时沿用该限制，不追溯扩大范围。

总体模型图的研究输入是已确认共享骨架、每问 report.md 中的 Model Delta、真实参数到组件的作用关系、来源版本与已确认边界。Model Delta 只在 [现有模板](../templates/records.md) 定义；研究侧整理已有证据不代表补做实验，Figure/Paper 不从运行日志猜模型。记录缺失先查真实来源，模型确未形成则记研究缺口；不为画图制造新确认点或追认旧计划。模型图渲染后还须做指南中的 10～20 秒快速可读性检查，结果写入原图索引，不能以“图已生成”通过。

每张正文图有 Why（图前阅读目的）、What（对象、数据、单位、比较范围）、So What（图后真实主要发现）和 Then What（帮助认识结构或支持何种判断）。不得只有“如图所示”；描述性图可明确未改变模型选择。结构图的“发现”可为读者应理解的真实关系，不捏造实验结论。

registry 由当前获授权的写入者串行更新；独立 Figure 任务只写其指定代码/输出和交回条目，主执行者合并，Reviewer 保持只读。生成时记录源与输出哈希/版本、命令和实际执行；技术复现与科学核验、逻辑核对、视觉验收分开，不用一项“已生成”冒充全通过。输入/逻辑/代码变化标记相关图待重生成/复核，并标出受影响章节；冻结版本不覆盖。图形相关 AI 使用由主执行者汇入同一 AI 使用日志。
