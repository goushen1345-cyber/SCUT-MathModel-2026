# 一条证据链，多个用途

任何重要操作形成：观察及来源 → 判断 → 候选 → 决策 → 理由 → 执行 → 核验 → 边界。记录可审查的理由与结果，不要求隐含思维过程。讲解写在聊天，技术证据写入文件，论文表述由同一事实派生。

## 最小账本

- state/state.json：唯一正式运行状态与授权引用；state.md 由脚本生成。
- state/decisions.md：按 ID 追加理由、候选、真实人类选择和版本；不再维护重复 rationale.md。
- state/ai_usage_log.md：重要任务后追加、阶段末汇总，记录工具/版本、用途、主要提示、产物、采用、人工修改和核验；人类未实际核验必须记待核验。
- questions/Qk/experiments.md：实验索引；每次运行的详细证据在 runs/<id>，记录数据/协议/代码/配置/环境/种子/终止条件/指标/失败。
- paper_evidence/data.md 与 Qk.md：主张、来源 ID、图表、支持状态、适用边界和可写表述。不把未支持结果当确定结论。

## 演化真实性

候选未试跑的淘汰理由只能是适配或成本判断；运行失败不自动证明方法差。M0 → 问题证据 → 改动假设 → M1 → 对照结果 → 保留/放弃。基础模型胜出、无显著改善、收益与风险取舍都是合法结论。论文可压缩过程，不隐瞒改变结论的反证。

## 独立验证与解释

最终数值追溯数据、代码、配置、运行和图表版本；检查器尽量采用独立路径、小样例或手算，不复制主程序错误。统计关联不等于因果，SHAP 不作现实因果证明。正文关键主张要能直接找到证据，完整日志不必堆入正文。

## 审查接口

按 workflow/templates/records.md 中的审查格式生成 review_packages/<审查ID>/review_package.md，使用本次冻结/候选版本的文件清单和哈希。外部对话不一定能访问本机路径：说明需上传哪些实际文件。截图只补充，不能替代公式、代码和输出。

审查对象含题面原文、协议、候选与失败结果，不只给 Worker 的推荐。Reviewer 默认只读，问题应给证据、影响、复现方法；允许材料不足。Worker 逐项记接受/反驳及证据/待检验；新权限回确认点。Reviewer 不能批准冻结，AI一致也不是独立验证证明。

独立审查使用 ../../.agents/skills/cumcm-reviewer/SKILL.md。Worker 生成的包还须说明本轮改动、上次问题ID及状态、当前拟作决定、直接/间接受影响产物。主执行者将 Reviewer 的工具、用途和真实核验活动汇入 AI 使用日志，不把 Reviewer 检查记成人工核验。Reviewer 不自己改共享账本。每条反馈的关闭需要修正版本与验证证据，不能仅凭“已修复”关闭。
